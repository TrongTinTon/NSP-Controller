NSP Controller 1.4.21 validation scope

Architecture
- Controller is Acquisition / Execution only.
- Normal RFID acquisition forwards every valid physical observation to the Parking raw-detection outbox.
- Calibration acquisition is an explicit execution scope supplied by Edge.
- Calibration routing is per-Reader: only Reader SDK Serials explicitly listed in the active Calibration Session are routed to the Calibration outbox.
- Other Readers continue normal raw acquisition while Calibration is active.
- Parking and Calibration outboxes drain independently.
- Controller does not receive/cache/evaluate Parking Layout, logical Lane, Antenna Sequence, direction, Check-in/Check-out, Vehicle/User authorization or Parking Transaction state.
- Controller never filters raw detections by a business Port/Antenna whitelist.

Reader execution
- Reader-wide RF power is applied through SetRfPower.
- Read interval is applied through SetInventoryScanTime.
- TID start/length are active Inventory_G2 request parameters.
- No per-port antenna power/topology/routing command exists in Controller runtime.
- Applied configuration is recorded only after the SDK configuration call succeeds.
- Reader UI shows last-confirmed Applied From, RF Power, effective Read Interval, TID Start, TID Length and Applied At.

Calibration safety
- Calibration execution lease defaults to 30 seconds and is refreshed by successful Edge pulls.
- Lease expiry clears only the execution context and returns Readers to normal acquisition.

Validation limits
- Static source/contract/XML/package validation performed.
- Windows .NET Framework 4.8 MSBuild and physical CF-E718 Reader tests are still required.
