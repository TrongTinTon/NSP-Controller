NSP Controller 1.4.17 validation scope

- Vendor C# package and UHFReader288.DLL manual V2.1 reviewed.
- x86 and x64 UHFReader288.dll files are managed .NET assemblies.
- Vendor SDK loading, method lookup, callback adaptation and connection state are isolated under Readers/CFE718/Sdk.
- Factory, discovery, identity, Reader-level technical configuration, inventory and runtime lifecycle are separated by responsibility.
- Controller discovers and reports physical Readers without business validation.
- Reader-wide power_dbm is applied through the scalar SetRfPower overload (0-33 dBm).
- No per-port antenna power, antenna topology, or antenna routing command exists in Controller runtime.
- port_no is sourced from the SDK callback and is not replaced with the acquisition-loop port.
- Lane Calibration status ready and running are both active Controller runtime states.
- Terminal Lane Calibration statuses cannot be reactivated by a stale desired_state value.
- Controller UI refreshes after every Lane Calibration pull result is applied or cleared.
- Edge remains responsible for the ready-to-running business transition after the first accepted raw event.
- Static source/XML/package validation only; Windows .NET Framework 4.8 MSBuild and physical Reader tests are still required.

- Idle detections are not queued or pushed to Parking.
- Parking outbox is transmitted only while Parking runtime is active.
- Core API nested business envelopes are unwrapped before runtime state parsing.
